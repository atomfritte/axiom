# Tasks

AXIOM does not model priority, it models start energy: how hard the cold start is. That is the most important difference to any other task list.

The usual problem is not knowing which task is the right one. It is starting it. A list sorted by importance puts exactly the task with the highest cold start at the top — and there it sits, for weeks.

## The four inputs

- **Start energy**, 1 to 10 — how hard the beginning is, not how long it takes
- **Consequences**, 1 to 10 — what it costs if it stays undone
- **Deadline** — when it starts to hurt; it drives urgency but is not an appointment
- **Place** — only needed if the task cannot be done elsewhere

Visible is whatever sits below today's capacity. The order comes out of consequences times deadline pressure divided by start energy — the same formula everywhere, no second yardstick, and not rearrangeable.

![The task list, in the order the system picks by.](img/aufgaben.webp)

The list has fixed sections: *Running*, *Within reach*, *Elsewhere*, *Not within reach*, *Split*, *Done*. "Not within reach" is a measurement, not a reproach: the start energy sits above what today carries. Tomorrow that can be different.

## Splitting

When something important stays out of reach, no reminder follows — a split does. And the question is deliberately not "what parts does this fall into". That gets answered with a project plan, and a project plan is itself a task with high start energy.

The question is: **what is the very first physical action?** Something that is done in two minutes.

![Splitting: the first action, a catalogue of shapes, and a target mark for the start energy.](img/zerlegen.webp)

AXIOM proposes no sub-steps. It cannot know what "sort out the tax papers" concretely means for you, and guessing here would be worse than silence. What it contributes: the question, the catalogue of shapes, and a check on whether the step really sits below the target.

Splitting works at any level — including on a sub-step that turns out to still be too big, and on a task AXIOM would not have offered by itself.

## The run-up

If a task carries a deadline, AXIOM also calculates the run-up: cold start plus working time. Once the run-up grows larger than the time left, the number appears on the task.

The moment in which starting would still have been enough is invisible from the inside. AXIOM names it once and passes no judgement — what follows from it is yours to decide.
